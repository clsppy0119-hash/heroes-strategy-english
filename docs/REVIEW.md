# Review 標準

每個可發布的里程碑走 feature branch 與 PR，CI 通過才合。所有結論留在 GitHub——聊天記錄不算數。

2026-08-11 起實作與 review 由同一方（Claude）負責，所以「第二意見」這層不再存在。少了一個人看，PR 的說明就得補上那個人本來會問的問題，而不是只寫「做了什麼」。

## PR 說明要回答的

- **為什麼是這個做法**，以及什麼情況下它會是錯的。只寫改了什麼等於把判斷藏起來。
- **驗證到什麼程度**。「測試通過」不算，要說跑了哪些、涵蓋什麼、沒涵蓋什麼。
- **守衛有沒有被驗證過**。新增的 CI 檢查要做反向測試：塞一個違規進去確認它會失敗，再移除確認會通過。只看到綠燈不能證明守衛有在守。
- **哪裡偷懶了**。刻意留下的取捨要寫出來，不要等它變成別人踩到的坑。

## 優先檢查

- 正確性與可重現性：戰鬥能不能用 `(初始狀態, seed, rulesVersion, 作答序列)` 重播。
- 交易與重試：資源扣除、結算與佔領是否在單一交易內完成。
- 安全：RLS、AI context 最小化、金鑰不進瀏覽器。
- **英文有沒有變成強制門票**，以及反過來——有沒有變成可以無視的裝飾。兩邊都是失敗。
- 領域邏輯耦合：`src/core` 有沒有偷偷相依 UI 或瀏覽器（`pnpm check:core` 會擋，但繞得過去的寫法要靠人看）。
- migration 能不能回滾。
- 手機 UX。
- 測試缺口。

## 不提供給任何外部工具

`.env`、金鑰、真實玩家資料、未去識別的學習紀錄。
